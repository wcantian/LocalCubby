## 问题与修复

| 问题 | 根源 | 处理 |
|---|---|---|
| npm registry 指向已废弃的 `registry.npm.taobao.org` | 全局 npm 配置陈旧 | 安装时显式 `--registry=https://registry.npmmirror.com` 并设置 `ELECTRON_MIRROR`，不改用户全局配置 |
| Electron 32+ 移除 `File.path`，拖拽取不到磁盘路径 | API 变更 | preload 暴露 `webUtils.getPathForFile`，渲染进程经 IPC 桥调用 |
| preload 的 `window.api` 类型声明与渲染进程冲突 | 两处 d.ts 同时声明全局 Window | 删除 `src/preload/index.d.ts`，统一放 `src/renderer/src/global.d.ts`，并按最小暴露原则内联接口，避免把 electron/node 类型带进 web 项目的类型检查 |
| CSP 会拦掉 Vite dev 注入的内联 React Refresh 脚本（dev 白屏） | `script-src 'self'` 不允许内联 | CSP 增加 `'unsafe-inline'` 并放行 `connect-src http://localhost:*`，dev 模式实测启动正常 |
| 冒烟测试「标签卡片排序」断言失败 | 断言写错：拼音序 `xiang`（项目）应排在 `xie`（协议）之前，代码输出正确 | 修正断言期望值，不改业务代码 |

### 问题与修复

| 问题 | 根源 | 处理 |
|---|---|---|
| 首次提交把 `.git-commit-msg.txt` 一起提交了 | 该临时文件在 `git add -A` 之前就已落盘在工作区 | 用一次独立提交删除，不做 `--amend` + force push（禁止强推 main） |

### 截图方式的选择

没有手绘 UI 稿或占位图，而是用 CDP 驱动真实运行的应用截图：启动打包 exe（`--remote-debugging-port`）→ 通过 `Runtime.evaluate` 切换界面状态 → `Page.captureScreenshot`。好处是 README 里的图与实际渲染永远一致，且截图流程可重复执行。
